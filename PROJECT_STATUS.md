# Project status

## Summary

- Phases 1-3 complete and verified (registry, graph engine, Python indexer, container/API/datastore extractors, watcher, CLI, tray app, docs extractor, git/PR/issue history). Phase 4 (enterprise federation) is design-only, intentionally unbuilt.
- Implementation Plan #5 (live web dashboard) shipped: a FastAPI+uvicorn server on its own daemon thread inside the tray process, serving a single hand-written HTML/CSS/JS file (`static/index.html`, with Cytoscape.js 3.30.2 vendored under `static/vendor/` and shipped as package data, so it works offline and loads nothing from a CDN; license in `THIRD_PARTY_NOTICES.md`) at `http://127.0.0.1:8765` with live push over Server-Sent Events. It is loopback-only with no authentication (single-user local tool). Graph exploration remains read-only; repository registration is the dashboard's bounded write action and runs the same initial scan as the CLI. The browser never holds Neo4j credentials — every graph query goes through a backend proxy (`POST /api/cypher` and related routes) running against the same `GraphEngine` the tray/watcher/MCP server use. Git history, query telemetry, and settings panes are backed by real data (`git_info.py`, `query_log.py`). The Query telemetry card's MCP half is wired to `GET /api/mcp-telemetry` and shows real tool-call totals, top tools, nearest-rank P50/P95/P99 latency and error rate over the newest 500 records the MCP server wrote (metadata only — no query text or arguments; a project tool is recorded as `<repo_id>_<name>`, a global one as `gl_<name>`, a built-in by its bare name, each with an origin), read from a local file so the card works with Neo4j down. That endpoint cannot tell an empty store from a missing or unreadable one, so those rows stay dashed and labelled in both cases instead of reporting zeros, and each figure discloses the sample it was computed over. Of the card's Neo4j rows, active queries is attempted live via `SHOW TRANSACTIONS` and queued transactions has no source on this build. The Database & memory card is backed by `dashboard/db_metrics.py`: a 15-second sampler (one hour in memory) reading heap, RAM, swap, CPU and GC from the JVM's own JMX beans, the configured page cache size from `dbms.listConfig`, and store size from a walk of `DEVGRAPH_NEO4J_DATA_DIR`; each group is independently live or labelled unavailable, and page cache hit ratio has no source on Community. The force-directed graph settle uses a Barnes-Hut quadtree for repulsion, and query highlighting can dim non-matching entities without rebuilding the canvas.

Tree-sitter extractors under `devgraph/indexer/jsts/`, `csharp/`, `cpp/`, `java/`, `rust/`, and `go/` dispatch by file extension alongside Python, dynamically per file rather than one language per repo, sharing `Module`/`Class`/`Function`/`CONTAINS`/`CALLS`/`IMPORTS`/`EXTENDS` node/edge shapes through `devgraph/indexer/common.py`. Each was checked against a real public project before merge. - Hardening pass (crash/instability quick wins) shipped: `index_paths` no longer aborts a whole batch on one bad file — each file is extracted in its own guarded step (`_index_single_path`) and logged/skipped on failure. The tray's health-check loop, quit/pause/dashboard-open paths, and `main()` are all exception-guarded so a background-thread or startup failure can't silently take down the watcher/indexer or leave a stale PID file. `GraphEngine` retries transient Neo4j errors (`ServiceUnavailable`/`SessionExpired`/`TransientError`) with bounded exponential backoff on every idempotent write and `verify_connectivity` (each retry is one line, `Neo4j not answering on try N of 4` for a refused connection, with no traceback; a warning in the agent, INFO in the CLI so a command shows only its final error) (arbitrary `run_cypher`/`run_cypher_graph` queries are deliberately not retried). `RepoRegistry` uses WAL journal mode, a 5s `busy_timeout` for cross-process access, and an idempotent `close()`. Git-history sync and the dashboard's git-status/log paths tolerate empty repos (no commits yet) and commits with no author/message. Removed dead code in `dashboard/routes.py` that would have raised `NameError`.

- Data-loss fix: `delete_nodes_by_source_file` used to `DETACH DELETE` any node whose `source` property matched the edited file — wrong for nodes several files legitimately co-produce (e.g. a `Service` defined in both `docker-compose.yml` and an override file), which destroyed the node outright when either file was edited. Those nodes (the ones without a `file` property — `Container`/`Service`/`Network`/`Volume`/API/Database-ish) now accumulate every producing file into a `sources` property on upsert; deleting a file unclaims it from `sources`, and the node is only removed once no file claims it.

- Batch order and graph accuracy (#1). Within one `index_paths` batch (a full scan, or a watcher batch), cross-file edges do not depend on file order. See `docs/superpowers/specs/2026-10-08-graph-accuracy-design.md`.
  - Every file's nodes are written first. Then source-file edges, docs-note edges (`SUPERSEDES`/`DECIDED_BY`/`links`) and Markdown `MENTIONS` are resolved against the whole batch.
  - A node several files produce (a `Datastore`, `Endpoint` or `Container` written with a `source`, or a C++ `Class` stub) doesn't depend on write order either. It keeps each claiming file's properties in `claims` (JSON with sorted keys), and `sources` stays sorted. Its properties are those of the alphabetically first source, re-attributed when that file stops claiming it. This replaced last-writer-wins, so a full scan now gives the first file's properties, not the last one's.
  - A route's handler stub is its own file-less `Function`. It never claims a real `Function` of the same name, so the graph is the same whichever file is written first. A FastAPI or Flask `Endpoint` `IMPLEMENTS` the stub and the route file's own function of that name, never a same-named function in another file. A Django `Endpoint` (views imported from `views.py`) still `IMPLEMENTS` every real function of that name, until imports are resolved. A C++ out-of-class method (`void Widget::draw() {}`) claims a file-less `Class` stub for its qualifier the same way: it never merges onto the header's `Class`, and it goes with the last file that defines a method of it.
  - Across batches, a batch re-indexes outside files that refer by name to a node it adds: docs notes whose `SUPERSEDES`/`DECIDED_BY`/`links` name it, route files with a handler stub of a new Function's name, and (until index format 7) same-directory, same-extension Java/Kotlin files naming a new class. Since format 7 no file is re-indexed as an importer of a changed one: every code edge is a function of its writer's text, its resolver configuration and whether its target exists.
  - Markdown that mentions an added name (when mentions are enabled) gains `MENTIONS` edges to just the added names, without a full re-index. A shared `Container`/`Datastore`/`Endpoint` (or C++ `Class` stub) counts as added when a batch file newly claims it, so one deleted with its last claim and claimed again links back. For a name that already exists, these files come from existing `MENTIONS` edges; only names new to the graph need a text scan. At most 25 files are relinked per batch; the rest wait for a rescan.
  - In `skip` mode, adding a second node with an already-mentioned name leaves the existing `MENTIONS` edges until the doc is re-indexed (which drops them) or rescanned.
  - Edge sources are pinned to their file; only targets stay bare-name. Same-named functions in two files no longer share call edges.
  - Built-in extracted edges carry a sorted `origins` list of the files that wrote them. Provider edges, git-history `MODIFIES` and PR `RESOLVES` edges have none. A file's re-index retracts only the edges it no longer writes. So a removed call, base class, import, compose service or Markdown mention goes on the next save. `origins` is hidden in the dashboard's edge inspector.
  - Each Module records the by-name edges its file wrote in `name_refs` (reserved, and hidden like `claims` by `describe_node` and the dashboard's node inspector). When a batch adds a node that an outside file's by-name edge named, that edge is re-written from `name_refs`, with no file read and no cap. Examples: an `IMPORTS` of a new module, a supertype in another directory, `CALLS` from outside the batch, a restored import target.
  - Every full scan stamps the index format as `Repository.index_format` (now 9: format 2 added `origins` and `name_refs`, 3 pins FastAPI/Flask `IMPLEMENTS`, 4 resolves Python `IMPORTS` and `CALLS`, 5 indexes `.mjs`/`.cjs`/`.mts`/`.cts`, resolves explicit-extension JS/TS imports such as `./x.js` to `x.ts`, and extracts compose `depends_on`/`links` as `Service` `DEPENDS_ON` edges, 6 resolves JS/TS `CALLS` and tsconfig aliases, adds path pins and Module `dir`/`basename`, records the resolver configuration fingerprint, and recovers Kotlin declarations after one-line class bodies, 7 resolves Go, Java and Kotlin `CALLS` and `IMPORTS`, 8 resolves Rust, C# and C++ `CALLS` and `IMPORTS` and fingerprints Cargo.toml crate names, 9 has a C++ out-of-class method's file claim its `Class` stub and deletes the unclaimed stubs an older index left). An older index is upgraded automatically; the upgrade's full scan drops a route's cross-file `IMPLEMENTS` edges. The agent's schema rescan scheduler runs a full rescan of an outdated, watched repository at its next pass, with no quiet period. The start catch-up runs a full scan instead of its incremental pass. Both check the stamp again under the repository's batch lock, so only one of them scans. A failing upgrade is retried after 30 s, doubling to at most 30 minutes; the delay resets on success. `devgraph status` lists an outdated repository as `rescan pending` until then. An unwatched repository needs `devgraph rescan`.
  - A repository that was never indexed has no stamp, but that doesn't count as outdated for the schema rescan scheduler. Its first scan is left to `devgraph add` or `devgraph rescan`, which may still be running. When the agent starts (or Resume), though, the start catch-up of a still never-indexed repository is a full scan, so a first scan cut by the last shutdown is redone; a `devgraph add` still running at that moment can overlap it. A full scan sets the index format to 0 while it runs and restamps it at the end, so a scan cut short (a schema rescan included: the schema is recorded before the files are written) is redone in full by the next catch-up.
  - Python call resolution (#1, audit B7/B8; `docs/superpowers/specs/2026-10-10-python-call-resolution-design.md`). An import targets every candidate file under the importer's ancestor directories (`p.py`, `p/__init__.py`, and `P/n` for `from P import n`), so flat, `src/` and nested layouts resolve without configuration; only existing Modules link. A call resolves, first match wins, to a def in the file or an enclosing function, an imported name's module (and any file under its package, for re-exports), `self`/`cls`/`super()` methods in the class or its bases (an imported base's module, not followed further), a module attribute, or a receiver typed by a parameter annotation, a same-file pytest fixture or `x = X(...)`. Edges carry `confidence`: `resolved` (a file the caller names), `package` (under an imported package) or `name` (an untyped receiver, linked by name). A builtin type's method on an untyped receiver, a literal receiver, and a bare name nothing defines or imports link nothing. Every Python edge is a function of its writer's text and whether its target exists: `name_refs` record pinned and package targets, and the relink restores them, so Python files are no longer re-indexed as reverse dependents of a changed import target (nor, since index format 7, Java ones). Graph insights leave out `name` and `package` calls; `find_callers` returns each caller's best `confidence`, resolved first, and takes `resolved_only`. On DevGraph itself multi-target call edges fell from 26,028 to 3,791 and the PageRank top ten holds no test helper or builtin method name. Recall losses: deeper cross-file inheritance, untyped receivers calling builtin-type method names, dynamic dispatch, and an untyped receiver's call of a name the same caller also resolves elsewhere (`subprocess.run()` beside `runner.run()`).
  - A seeded multi-language fuzz (`tests/indexer/test_graph_accuracy_fuzz.py`, live) checks that incremental batches equal a fresh full scan after every step of random edits, deletes, restores, renames and symbol moves. `DEVGRAPH_ACCURACY_FUZZ_SEEDS` and `DEVGRAPH_ACCURACY_FUZZ_STEPS` lengthen it.

  - Class, Function and Service have a `(repo_id, name)` RANGE index (`<label>_repo_name_lookup`, created by `init_schema` on every scan and MCP start, so existing databases get it). A bare-name edge target used to scan every node of the label; it is now an index seek. Each end of a Class, Function or Service edge carries a `USING INDEX SEEK` hint (a pinned end on its `(repo_id, name, file)` unique index, a bare-name end on the lookup index), and so does the relink's Module read. A plan made from index statistics taken while the label was near-empty estimates 0 rows and could otherwise scan a whole index per row, which a plain `USING INDEX` hint still allows (a 5,000-module relink took 8 to 23 s instead of under 1 s in CI). A single-file save of `devgraph/cli/main.py` on this repository went from about 51 s to about 2.7 s.
  - Call resolution beyond Python, slice A (#1, audit-2 items 4, 7, 11, 12; `docs/superpowers/specs/2026-10-11-nonpython-call-resolution-design.md`). Shared core: `devgraph/indexer/calls.py` (`call_rows`, per-language `STOP_METHODS`/`STOP_TYPES`, `no_self`, which keeps `x.save()` inside `save` off itself) and path pins in the engine: an anchored directory (`a/b/.`, resolved), a path suffix (`/a/b/C.java`) and a suffix directory (`/a/b/.`) (package), beside Python's recursive prefix, with a `!suffix` exclusion and precedence carried as `exclude` pin patterns; `common.pin_matches` defines them and the Cypher is checked against it. Modules carry `dir`/`basename` for pinned `IMPORTS`. Resolver configuration (`devgraph/indexer/resolver_config.py`): a JS/TS file's nearest tsconfig/jsconfig, with `extends` and `references`, gives its path aliases; a fingerprint of every tsconfig and go.mod/go.work is stored on the Repository node, and a live batch touching one, or a catch-up, re-indexes that language when it changed.   - Call resolution, slice C (index format 8; same spec). Rust resolves through crate roots (the nearest `src/`; `src/bin/*.rs` and the files of `tests/`, `benches/`, `examples/` are crate roots of their own), module paths (`crate::`, `self::`, `super::`, and `mod foo;` in `src/a.rs` now naming `src/a/foo.rs`), `use` bindings, `Type::f()` and typed receivers; another workspace crate is named through its Cargo.toml, now resolver configuration with a Rust fingerprint, at package confidence. Before a dead watchdog emitter is stopped again (unscheduled by the reconcile, or by the observer's stop), its closed Windows directory handle is forgotten: watchdog keeps the value and would close it a second time, by then perhaps another object's handle. The tray tooltip reads `DevGraph (catching up)` and the dashboard's Entities pill `Catching up…` while that runs. Pause watching waits up to 3 s (`STOP_WAIT_S`) for a running batch, catch-up or git-history sync, so it can block the tray menu that long. Quitting the tray or headless agent (`devgraph/agent/shutdown.py`) is ordered and bounded to 5 s in total (`SHUTDOWN_WAIT_S`): the dashboard is told to exit, the schema-rescan and insights schedulers stop (a rescan still waiting on the batch lock skips its scan), then the watcher, each waiting for its running work against one deadline, and the graph engine close gets the time that remains. With `cross_repo`, a not-found error says its suggestions come from the calling repository. An unknown repository or a bad ref is now a ToolError, not an `error` key.
- MCP tools no longer answer mistakes with plausible empty results (audit 2, item 9): every built-in called with an explicit `repo_id` checks the registry first (`no such repo_id`, so `summarise_repository` no longer returns zeros for a typo); `impact_analysis`, `get_service_dependencies`, `trace_request_flow` and `explain_decision` raise `no <thing> named ...` with up to five similar names (the same suggestions `describe_node` gives); `trace_design_rationale` drops the `{name: null}` rows its `OPTIONAL MATCH` produced; `max_results`, `within_commits` (which used to become `SKIP -1`), `modified_within_commits`, `members_per_community` and `max_per_type` below 1 and `max_length` below 2 are ToolErrors (upper bounds still clamp); `find_mentions` returns a notice when mentions indexing is off, like the PR and issue tools; and `trace_request_flow` accepts a bare path for every method, and no longer returns nothing for an endpoint without outgoing edges.
- Audit 3, items 1-8 (Linux first-run, security): the dashboard escapes every repository-sourced string it renders as markup (`escapeHtmlVal` also escapes quotes; the git panel's expanded commit detail, tree and hover card, console history, autocomplete and degree leaderboard were unescaped), checked by `tests/dashboard/xss_escaping.js`. The Cypher console's live preview sends `preview: true`, which `/api/cypher` runs in a read transaction (`GraphEngine.preview_cypher_graph`), so typing never writes. `DEVGRAPH_ALLOW_CROSS_REPO` is enforced: a gate on every built-in that takes `cross_repo` raises a ToolError unless it is on, and cross-repo queries match only registered repo ids (`tools.cross_repo_ids`); the dashboard's All Repos is bounded the same way. The tray hands pystray latin-1-safe text (the ellipsis crashed it on X11), falls back to the headless agent with no display or tray backend, `tray start` waits for the first heartbeat and `tray status` exits non-zero when down; the agent package no longer imports pystray eagerly. Claude Code registration is user-scoped everywhere, with local-scope leftovers detected. Doctor treats Podman as informational when Neo4j is reachable and checks constraints for registered repositories only; the watcher and accuracy-fuzz live tests sweep repositories a killed run left. `devgraph update` uses `uv sync` in a uv environment and always restarts the tray it stopped. The dashboard's repo list is built from the registry even when empty, with a register call to action.
- The watcher uses a bounded number of inotify instances (audit 3, item 9). watchdog opens one per scheduled watch and Linux allows 128 per user, shared with every other program; one watch per top-level folder used them up on a repository with ~100 folders (104 instances; now 1: one recursive watch on the root, whose instance also carries `.git`, `.git/refs` and `.git/refs/heads`, routed to the git handler by `_RootEventRouter`). On Linux (`ROOT_WATCH`) the root watch goes through `devgraph/watcher/inotify.py`, an emitter that keeps folders `full_scan` skips (`IGNORED_DIR_NAMES`, `.gitignore`) out of the kernel watch at any depth, watches folders moved in from outside (watchdog leaves them unwatched), adds watches after a `.gitignore` change un-ignores a folder (through the reconcile timer), and closes its descriptor and pipe when setup fails (watchdog leaks them); moves between top-level folders now pair. A kernel queue overflow (`IN_Q_OVERFLOW`, which watchdog drops silently) is detected and followed by a catch-up from `last_indexed` (reason `overflow`); the `.gitignore` re-watch walks outside the inotify lock. Windows and macOS keep one watch per top-level folder (ReadDirectoryChangesW buffer overflow on `.venv`/build trees) and its reconcile. A watch that fails to start stops and joins whatever started (no leaked threads, fds or instances) and records `watching unavailable: inotify limit reached (...)` with the sysctl to raise; `devgraph status` and `doctor` say `running, but not watching N repositories` with each reason (`doctor` fails), and the dashboard's repository picker marks the repository `(not watched)`. A folder whose watch can't be added mid-session (ENOSPC/EMFILE) is recorded as the same repository issue and followed by a catch-up (reason `unwatched`). Still open: that folder stays unwatched until restart; the emitter relies on watchdog internals: watchdog is pinned to 6.x, `inotify.SUPPORTED` checks for them at import (without them the watcher falls back to per-folder watches), and an exception in watchdog's reader is recorded as `watching stopped: ...` rather than ending the thread silently.
- Shallow clones get git history (audit 3, item 10): a `--depth` clone's boundary commits (`.git/shallow`) name parents the clone lacks, so diffing against them failed and those commits got no `MODIFIES` edges under a warning that blamed a partial clone. They are now read like root commits (every file in their tree counts as touched), as `git log` shows them. The registry keeps a digest of `.git/shallow` beside `last_indexed_commit` (`last_indexed_shallow`); when it changes (`git fetch --deepen`, `--unshallow`) the next sync reconciles, and every reconcile replaces each re-read commit's `MODIFIES` edges rather than adding to them, so a former boundary keeps only the files it changed; the warning for commits that still can't be read says their trees are missing (a partial or damaged clone). `blame_component` with a path no Module has raises a not-found ToolError with similar paths, like the other tools; a known file no commit touched still returns `[]`.
- The watcher's debounce has a maximum wait (audit 3, item 11): every event restarted the 500 ms debounce, so a file written more often than that (a log, build output) held off indexing for as long as the writes went on. File batches now fire no later than `watch_max_wait_ms` (`DEVGRAPH_WATCH_MAX_WAIT_MS`, default 5000) after their first event; a lone event still waits only the debounce. Events that arrive while a fired batch waits for the batch lock join it (no timer each). Git bursts keep the plain debounce, so a long rebase isn't caught up half-done.
- Dashboard keyboard and screen-reader access (audit 3, item 12): the themed selects are an ARIA combobox and listbox (arrow keys, Enter, Escape, the selected option announced; an option's title, such as why a repository isn't watched, carried onto its item), tooltips open on keyboard focus as well as hover, and icon-only buttons have labels.

## Commands

- **Canonical setup**: the README installer launches `.\scripts\setup-menu.ps1`, which creates the Python environment, installs DevGraph, starts Neo4j, initializes schema, runs `devgraph doctor`, and offers MCP client registration. Idempotent.
- **Update an existing checkout**: `devgraph update` — fast-forward pull, reinstall, `doctor`, and tray restart when needed. Commit or stash local changes first; `--force` only suppresses the dirty-tree guard. `.\scripts\update.ps1` remains as a compatibility entry point.
- Manual equivalent (any platform): `uv sync --extra dev` (or `python -m venv .venv` and `python -m pip install -e ".[dev]"` with that environment's Python: `.venv/bin/python` on Linux and macOS, `.venv\Scripts\python` on Windows) → start Neo4j with Podman or Docker (`docker` takes the same arguments):
  `podman run -d --name devgraph-neo4j -p 127.0.0.1:7474:7474 -p 127.0.0.1:7687:7687 -e NEO4J_AUTH=neo4j/devgraph-local-dev -v devgraph_neo4j_data:/data -v devgraph_neo4j_logs:/logs docker.io/library/neo4j:5.26-community`
  (`deploy/podman-compose.yml` is an untested alternative for compose-provider setups.) The README's Linux quickstart walks through the same steps.
- Tests: `uv run pytest` (or the environment's Python with `-m pytest`)
- Continuous integration: `.github/workflows/tests.yml` runs on every push and pull request (and on demand). The Linux job runs the full pytest suite against a Neo4j 5.26 service container, then the `tests/dashboard/*.js` node harnesses. The Windows job runs the same suite and harnesses without live Neo4j: the live tests skip there, so Windows covers everything but the graph round trips.
- CLI: run `devgraph --help` for the authoritative command list. Main groups cover repository registration and rescans; status, diagnostics, stats, and pruning; dashboard and tray control; MCP client setup; configuration (the `config` group: settings, schema list/add/edit/delete/reset, show/validate/eject, tools) and logs; graph export; annotations, mentions, git history, and PR/issue opt-ins; and self-update.

**Podman note**: on Windows, `podman.exe` may not be on PATH by default even when installed — check `%LOCALAPPDATA%\Programs\Podman` first. `devgraph doctor` needs Podman only while Neo4j is unreachable. Never install software to the host; dependencies live in `.venv/` and containers. Never touch containers/volumes not prefixed `devgraph-`.

## Structure

- `Blueprints/` — numbered design docs. `Design Brief #1.md` is the architecture source of truth. `Design Brief #2.md` is an unbuilt Phase 4 sketch. `Implementation Plan #2.md` covers rollout readiness + extraction quality (implemented). `Design Brief #3.md` and `Implementation Plan #3.md` cover response envelopes, `CALLS` scope narrowing, `impact_analysis_for_diff`, and a deferred embedding-search item (implemented except the deferred item). `Implementation Plan #5.md` covers the live dashboard (implemented).
- `devgraph/config/` — Pydantic settings; all security-sensitive defaults off (telemetry, cloud sync, cross-repo, `run_cypher`). `project_tools.py` loads and fail-closed-validates an optional repository-root `devgraph.tools.yaml` declaring read-only Cypher tools (served to MCP clients by `devgraph/mcp/tool_plane.py`). `project_schema.py` loads and fail-closed-validates an optional repository-root `devgraph.schema.yaml` declaring extra node types/relationships — the loader feeds the filesystem provider (`devgraph/indexer/providers/filesystem.py`), which indexes declared File/Folder-style node types and parent edges, and the docs provider (`devgraph/indexer/providers/docs.py`), which indexes node types and relationships from Markdown front matter; custom providers are still validated as data only and never run, and a repository without the file resolves to exactly the built-in labels, relationship types, and constraints.
- `devgraph/registry/` — SQLite-backed repo allowlist (`RepoRegistry`), thread-safe via `RLock`. Stores `docs_path`, `mentions_enabled`, PR/issue opt-in flags, `last_indexed_commit`.
- `devgraph/analytics/` — derived graph analytics: `insights.py`.
- `devgraph/graph/` — `GraphEngine` (Neo4j driver, idempotent MERGE, schema constraints, per-file delete cleanup) and `schema.py` (canonical labels/relationship types — import from here, don't hardcode strings).
- `devgraph/indexer/common.py` — `GraphNode`/`GraphRelationship`/`ExtractionResult`, shared by every language extractor below.
- `devgraph/indexer/python/` — Tree-sitter Python extractor. Modules keyed by repo-relative path. Extracts `CALLS` (resolved through scope and imports, with `confidence` and `caller_class` metadata for `find_callers`), `CONTAINS`, `IMPORTS` (every candidate file under the importer's ancestor directories; `resolve.py`), `EXTENDS`, docstrings (`description`/`docstring_full`), and `start_line`/`end_line` for `get_source`.
- `devgraph/indexer/jsts/`, `csharp/`, `cpp/`, `java/`, `rust/`, `go/` — Implementation Plan #8's six additional Tree-sitter extractors, same node/edge shape as the Python one. Since index format 8 every one of them resolves `CALLS` and `IMPORTS` through its language's own rules (see the call-resolution entries above); C++ reads quoted includes without the build's `-I` flags. JS/TS covers `.js`/`.jsx`/`.mjs`/`.cjs`/`.ts`/`.tsx`/`.mts`/`.cts`; an import with an explicit extension resolves to the source that emits it (`./x.js` to `x.ts`/`x.tsx`/`x.js`, `.mjs` to `.mts`, `.cjs` to `.cts`, then `x.js/index.*` for a directory); a `?query` or `#fragment` is dropped first. Candidates are not checked against the disk, so `./x.js` links both `x.ts` and `x.js` when both exist.
- `devgraph/indexer/kotlin/` — Kotlin Tree-sitter extractor (added after Plan #8's six), mirroring the Java extractor. Maps `class`/`interface`/`enum class`/`sealed`/`data`/`object` to Class, `fun` to Function, resolves `import` via Kotlin's package/folder convention; since index format 7 an import is an `IMPORTS` edge to the class or top-level function it names, in its package's directory (see the extractor's module docstring for the known-limitations list). Declarations after a one-line class body, which tree-sitter-kotlin 1.1.0 loses, are recovered (`_parse_kotlin`). `.kts` build scripts are intentionally not indexed.
- `devgraph/indexer/containers/`, `apis/`, `datastores/` — Podman Compose, route, and datastore-usage extractors. Container extractor captures `build_context` for service cross-linking, and a compose service's `depends_on` (list or map) and `links` (`name:alias` stripped) as `Service` `DEPENDS_ON` `Service`, both ends pinned to the compose file, so `get_service_dependencies`, `impact_analysis` and `find_dependency_cycles(relationship="DEPENDS_ON")` see them. Gaps: a compose file's `include:` and a service's `extends:` are not followed, an override file (`compose.override.yaml`, `-f a -f b`) is indexed as its own file rather than merged, and a dependency on a service declared in another compose file gets no edge (both ends are pinned to the declaring file).
- `devgraph/indexer/dispatch.py` — routes changed/deleted files to the right extractor (`index_paths`, `remove_paths`, `full_scan`); called by CLI, watcher, and tray app. Prunes stale nodes on re-index; links services to owning code via `build_context`.
- `devgraph/indexer/docs/` — Markdown front-matter extractor for `Requirement`/`DesignDecision`/`ArchitectureNote`.
- `devgraph/indexer/mentions/` — Markdown mention extractor detecting known entity references in code-like contexts (inline code, fenced blocks, call syntax `Name(`, declaration keywords); creates `Document` nodes and `MENTIONS` edges; configurable ambiguous-name handling via `mentions_ambiguous_mode` setting (`"all"`/`"skip"`).
- `devgraph/indexer/git_history/` — commit history via GitPython (local only). Automatically synced on every `.git` state change (branch switches, rebases, resets) via a dedicated watcher, including correct reconciliation of orphaned commits when history is rewritten. Stages denormalized recency properties onto `Module`/`Function`/`Class` nodes (via `git blame` for function/class-level `last_modified_at`); no `Function`/`Class`-level `created_at` (intentionally, since it would require `git log -L` which is too fragile). Author tracking via `git_recency_track_author` setting (off by default). Recency only annotates nodes that already exist (`stage_recency`/`set_recency` MATCH rather than MERGE), so a commit touching a README, an image or a deleted file no longer leaves a bare `Module` behind. So that the sync never reaches a file before the indexer does, the agent runs it after a git operation's catch-up, in the same job under the repository's batch lock (a CLI `rescan` indexes first, then syncs). Upgrade cleanup: `prune_stale_files` (every `full_scan`, and the agent's catch-up on start) deletes `Module` nodes with no `source_file`, `file` or `path`, which only the old MERGE made.
- `devgraph/indexer/pr_issues/` — opt-in GitHub PR/issue ingestion; hard-gated per-repo, off by default. With the flag off, `find_related_prs`/`issue_history_for` return an empty envelope with a `notice` (the old `gh` CLI fallback is gone: no tool reaches the network).
- `devgraph/watcher/` — `WatcherManager`, registry-scoped file and git-state watching with debounce. Watches `.git` and `.git/refs` non-recursively (HEAD, `packed-refs`, `index.lock`, `refs/stash`) and `.git/refs/heads/` recursively to detect branch switches/rebases/resets/stashes, triggering automatic history reconciliation after the post-git catch-up; handles atomic rename-saves correctly. A file rename queues the source as deleted and the destination as changed; directory deletes and moves queue the folder (expanded to exact files by `remove_paths`), and directory creates and in-repo moves are walked with `walk.indexable_paths_under`, one log line per folder. A create, delete or move at the top level asks for a watch reconcile on its own timer thread, which drops dead or stale watches (checked by emitter liveness and directory identity), schedules missing folders and walks them, retrying a failed schedule after 0.5, 1, 2 and 4 s before warning. Each repository has one batch lock (`run_exclusive`), shared with catch-ups, the schema rescan and dashboard registration; `on_changes` runs outside the handler's event lock. On start (and Resume, and a repository picked up by `refresh`), `last_indexed` is read before the watch starts and `on_catch_up` runs under the batch lock. A git burst (an `index.lock` tied to a HEAD or ref change) asks for a catch-up 2 s later from the burst's start, followed by the git-history sync in the same job; `request_catch_up` coalesces requests to the earliest `since`, and a request with a shorter delay replaces a pending one. Timers come from an injectable `timer_factory`. Design: `docs/superpowers/specs/2026-10-07-watcher-correctness-design.md`.
- `devgraph/mcp/` — MCP query implementations (`tools.py`) + server wiring (`server.py`). Most list-valued tools return `{count, results, truncated}` envelopes capped by `max_results`. All tools are read-only except `run_cypher` (gated behind config, off by default); built-in tools query through `_query` (`GraphEngine.run_read_cypher`: read access, `BUILTIN_TIMEOUT_S` = 30 s, a timeout raised as a ToolError), and so do `key_nodes`/`find_communities` through `insights.top_nodes`/`community_members`; `find_callers`, `find_mentions`, `list_recent_changes` and `blame_component` read at most `LIST_ROW_LIMIT` = 10,000 rows, and past it the envelope is `truncated` with a `notice` (blame returns the newest 10,000 commits) instead of failing, and impact traversal is bounded at `IMPACT_MAX_DEPTH` = 4 hops, expanded hop by hop over distinct nodes (each dependent listed at its nearest hop) rather than by variable-length paths, so a common name like `get` answers in well under a second instead of timing out. `tool_plane.py` resolves the session repository and registers the repository's `devgraph.tools.yaml` tools; built-in tools default `repo_id` to that session repository; `devgraph://project-tools` reports the scope, served tools and notices. Serves `devgraph://client-guide` and the generated `devgraph://tool-catalog` resource for client handover. Auto-starts/stops the tray app via refcounted holder tracking on connect/disconnect.
- `devgraph/cli/` — Typer CLI; see Commands above. `status` exits 1 when Neo4j or the registry is unusable and `add` when its initial scan fails; a Neo4j failure is one line naming the setting and the `.env` file to fix (`_neo4j_problem`); `remove --keep-graph` unregisters without Neo4j (then `devgraph prune` deletes the graph data once Neo4j is up); a registry SQLite error names the registry file.
- `devgraph/agent/` — `lifecycle.py`: PID-file/liveness/holder-refcounting for the tray app, shared by CLI and MCP server. `tray.py`: pystray shell wiring watcher + indexer + Neo4j health check + heartbeat file + the dashboard's own daemon thread. `sync.py`: `RepoSync`, shared by the tray and `headless.py`, indexes live batches, runs catch-ups (`dispatch.catch_up`: prune, then re-index files the graph doesn't know or whose change stamp is at or after `since` minus 5 s), stamps `last_indexed` with the start of the work, and on a failure holds the stamps back to a per-repository floor, warns, and asks for a catch-up 30 s later (and again when the health loop sees Neo4j recover). It publishes `catch_up` events (`running`, then `done` or `failed`) that drive the tray's `DevGraph (catching up)` tooltip and the dashboard pill.
- `devgraph/dashboard/` — FastAPI app (`app.py`: `build_app()`), `/api/*` read + Cypher-proxy routes (`routes.py`, backed by `GraphEngine.run_cypher_graph`), dashboard-shaped Cypher helpers (`queries.py`), real git log/status (`git_info.py`), in-memory query telemetry for the dashboard's own Cypher console (`query_log.py`), database and memory readings plus their sampled history (`db_metrics.py`), a read-only view of MCP tool-call metadata recorded by the MCP server processes (`/api/mcp-telemetry`, read from the local store `devgraph/mcp/server.py` appends to — never through the MCP stdio server), SSE pub/sub (`events.py`: `EventBroadcaster`), the agent's server start (`serving.py`: binds the port itself, so a port another program holds is a logged warning, a tray tooltip and a `devgraph status` line instead of uvicorn's silent exit; `GET /api/health` identifies the server, and `devgraph dashboard` refuses to open a port that doesn't answer as DevGraph), and `static/index.html` (single hand-written file, no build step, Cytoscape.js vendored under `static/vendor/`). A second, independent read-only consumer of the same `GraphEngine`/`RepoRegistry` the tray owns — never routes through the MCP stdio server.
- `tests/` — mirrors the `devgraph/` package.
- `deploy/podman-compose.yml` — declarative alternative to the `podman run` setup command.
- `DEVGRAPH-CLIENT.md` — portable doc for another repo's coding assistant to connect to this DevGraph instance.
